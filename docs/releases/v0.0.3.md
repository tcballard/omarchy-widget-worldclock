# World Clock v0.0.3 — four designs, correctly packaged

World Clock 0.0.3 packages Solar, Classic, Monolith and Twin with the component they need to load after installation.

We found that previews could work from a checkout while the installed widget failed: `ClockFace.qml` was missing from the installer. It is now included, and tests render the actual staged package for both fresh installs and updates.

- Solar and Classic support medium and large widgets; Monolith and Twin support small widgets.
- Choose digital or analogue display, edit cities, and save each instance independently through Core’s settings window.
- All four designs are exercised in light and dark themes at their supported sizes. The tests now supply the real widget family, so small layouts are checked properly.

**This is an experimental preview for Widget Core 0.0.3 / API 3.** The numbering is deliberately aligned with Core’s 0.0.x preview series. Core’s staged updates accept the change from earlier QML 0.1.2 and experimental 0.2.0 versions while retaining settings and rollback history.

The optional shared-renderer package is also versioned 0.0.3. It remains opt-in, does not reproduce the four QML designs, and makes no memory-saving claim.

Model, packaged-rendering, settings and declarative-update CI passed on the release PR. Live Hyprland focus, monitor changes, suspend/reboot and XPS resource acceptance remain open.

Update Core first. Finish any unsaved widget settings, then update an existing World Clock checkout:

```bash
git fetch origin --tags
git switch --detach v0.0.3
bash install-local --update
omarchy-widget restart
```

For a first installation, use `bash install-local`. Open `omarchy-widget manage` to choose a size and configure the clock. Please include the design, widget size and display scale with any rendering report.
